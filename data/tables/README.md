# The data tables, uncompressed

This folder holds readable copies of the data, for inspection outside the application.
The application itself reads the compressed files in `data/processed/`. Everything here is
generated by `scripts/12_export_tables.py`.

| File | Content |
|---|---|
| `eurepoc_global_dataset.csv` | **Initial table.** 3,414 incidents, the `incident_id` and the 18 attributes the project uses: 4 numeric and 14 categorical, with the original EuRepoC values |
| `eurepoc_global_dataset_123_indicators.csv` | **Encoded table.** 3,414 incidents, the `incident_id` and the 123 binary indicators that encode the 14 categorical attributes |
| `eurepoc_global_dataset_codebook_14_to_123.csv` | For each indicator: the attribute and the category it comes from, and how many incidents have it |
| `Threat-Shape_tables.xlsx` | The three tables above in one workbook, plus the number of indicators per attribute |
| `uncompressed/` | The `.csv.gz` files of `data/processed/`, decompressed (see the last section) |

## Source

European Repository of Cyber Incidents (EuRepoC), *Global Dataset of Cyber Incidents*,
version 1.3.2, file `eurepoc_global_dataset_1_3.csv`: <https://zenodo.org/records/14965395>
(doi:10.5281/zenodo.14965395), licensed CC BY-NC 4.0. One row per incident: 3,414 rows and
85 columns.

## From 85 columns to 18 attributes

Every one of the 85 columns was classified (`scripts/00_verify_data.py`,
`docs/phase0_report.md` section 4). 18 describe *what the incident was* and are kept; the
other 67 are excluded for one of these reasons:

| Columns | Reason for excluding them | Examples |
|---:|---|---|
| 11 | Degenerate: one value covers more than 90% of the rows | `zero_days`, `casualties`, `user_interaction` |
| 10 | Detailed subcategory of a kept attribute | `receiver_subcategory`, `il_breach_indicator_subcode` |
| 9 | Free text or names | `name`, `description`, `initiator_name` |
| 7 | Dates | `start_date`, `end_date`, `added_to_db` |
| 7 | Geography: used by the map, not by the projection | `receiver_country`, `initiator_country` |
| 5 | Binned copy of a kept numeric attribute | `impact_indicator_label`, `unweighted_intensity` (r = 0.97 with the weighted one) |
| 5 | Attribution metadata: how well an incident was documented, not what it was | `attribution_type`, `source_disclosure` |
| 4 | Identifiers and codes | `incident_id`, `attribution_id` |
| 4 | Redundant with a kept column | `has_disruption`, `response_indicator` |
| 3 | Counts of related records | `number_attributions` |
| 2 | Source URLs | `source_url` |

The 18 attributes kept:

| Kind | Attributes |
|---|---|
| Numeric (4) | `weighted_intensity`, `impact_indicator_score`, `affected_entities_value`, `affected_third_countries_value` |
| Categorical (14) | `incident_type`, `mitre_initial_access`, `mitre_impact`, `functional_impact`, `intelligence_impact`, `cyber_conflict_issue`, `offline_conflict_issue`, `il_breach_indicator`, `initiator_category`, `state_responsibility_actor`, `receiver_category`, `data_theft`, `disruption`, `hijacking` |

The 4 numeric attributes are ordered scales, so they stay numeric: a one-hot encoding would
lose the order. The AS index, counted on the attributes before encoding, is
3,414 × 18 = 61,452.

## From 14 categorical attributes to 123 binary indicators

**1. One indicator per category.** Each categorical attribute takes its values from a fixed
list of categories. Every category that occurs at least once in the corpus becomes a
column, which is 1 if the incident has that category and 0 if it does not. The 123
indicators are the sum of the categories of the 14 attributes:

| Attribute | Indicators | Categories |
|---|---:|---|
| `incident_type` | 7 | Data theft; Data theft & Doxing; Disruption; Hijacking with Misuse; Hijacking without Misuse; Ransomware; Not available |
| `mitre_initial_access` | 10 | Drive-By Compromise; Exploit Public-Facing Application; External Remote Services; Hardware Additions; Phishing; Replication Through Removable Media; Supply Chain Compromise; Trusted Relationship; Valid Accounts; Not available |
| `mitre_impact` | 14 | Account Access Removal; Data Destruction; Data Encrypted for Impact; Data Exfiltration; Data Manipulation; Defacement; Disk Wipe; Endpoint Denial of Service; Firmware Corruption; Network Denial of Service; Resource Hijacking; Service Stop; System Shutdown/Reboot; Not available |
| `functional_impact` | 6 | Day; Days; Weeks; Months; No system interference/disruption; Not available |
| `intelligence_impact` | 6 | five levels of data breach and data corruption; Not available |
| `cyber_conflict_issue` | 13 | Autonomy; Cyber-specific; Decolonization; International power; National power; Resources; Secession; Subnational predominance; System / ideology; Territory; Other; Unknown; Not available |
| `offline_conflict_issue` | 12 | Autonomy; International power; National power; Resources; Secession; Subnational predominance; System/ideology; Territory; Third-party intervention; Other; Unknown; Not available |
| `il_breach_indicator` | 20 | Aid and development; Air law; Armed conflict; Cyber espionage; Diplomatic / consular law; Disaster management; Due diligence; Human rights; Intellectual property law; International criminal law; International economic law; International organizations; International peace; International telecommunication law; Law of the sea; Law of treaties; Self-determination; Sovereignty; Space law; Not available |
| `initiator_category` | 7 | Individual hacker; Non-state-group; State; State affiliated actor; Other; Not attributed; Unknown |
| `state_responsibility_actor` | 4 | Direct; Indirect; None/Negligent; Not available |
| `receiver_category` | 12 | Corporate Targets; Critical infrastructure; Education; End user / specially protected groups; International / supranational organization; Media; Science; Social groups; State institutions / political system; Other; Unknown; Not available |
| `data_theft` | 4 | sensitive information; non-sensitive information; none; Not available |
| `disruption` | 4 | Short-term disruption; Long-term disruption; none; Not available |
| `hijacking` | 4 | Hijacking, not used; Hijacking, system misuse; none; Not available |
| **Total** | **123** | |

The codebook file lists all 123 categories with their full EuRepoC wording.

**2. Several categories in one cell: multi-hot, not one-hot.** A EuRepoC cell can hold
several categories separated by `;`. The incident then has a 1 in each of them, so within
one attribute more than one indicator can be 1. This happens in 6 of the 14 attributes:

| Attribute | Incidents with several categories |
|---|---:|
| `incident_type` | 1,731 |
| `il_breach_indicator` | 1,319 |
| `receiver_category` | 926 |
| `offline_conflict_issue` | 821 |
| `cyber_conflict_issue` | 748 |
| `initiator_category` | 31 |

**3. Splitting a cell.** A cell is split on `;` only outside parentheses, because some
categories carry an explanation in brackets that itself contains a `;`, for example
`Long-term disruption (> 24h; incident scores 2 points in intensity)`. A category repeated
in the same cell counts once (`scripts/eurepoc_atoms.py`).

**4. Missing values are categories.** `Not available`, `Unknown`, `None` and `Not attributed`
keep their own indicator instead of being dropped: a missing attribution or an undocumented
access vector is itself information. Every incident therefore has at least one 1 in every
attribute.

**5. The 4 numeric attributes stay numeric.** In the matrix used for the projection,
`affected_entities_value` becomes log(1 + x), because it ranges from 0 to 1,000,000; the
other three are unchanged. The 123 indicators and the 4 numeric attributes make the 127
columns of `data/processed/features_matrix.csv.gz`, which are standardized before PCA and
t-SNE.

### A worked example: incident 4163

*Russian State-Sponsored Actors Linked to GRU Disrupted Ukrainian State Registries in
Cyber-Attack on 19 December 2024.*

| Attribute | Value in the initial table | Indicators equal to 1 |
|---|---|---|
| `incident_type` | Disruption;Hijacking with Misuse | `type_disruption`, `type_hijacking_with_misuse` |
| `mitre_initial_access` | Not available | `access_not_available` |
| `mitre_impact` | Data Destruction | `impact_data_destruction` |
| `functional_impact` | Weeks (< 4 weeks) | `fimpact_weeks` |
| `intelligence_impact` | No data breach/exfiltration or data corruption… | `iimpact_no_data_breach_exfiltration_or_data_corr` |
| `cyber_conflict_issue` | International power | `issue_international_power` |
| `offline_conflict_issue` | Territory;International power | `oissue_territory`, `oissue_international_power` |
| `il_breach_indicator` | Armed conflict;Sovereignty | `ilaw_armed_conflict`, `ilaw_sovereignty` |
| `initiator_category` | State | `init_state` |
| `state_responsibility_actor` | Direct (official members of state entities…) | `stateresp_direct` |
| `receiver_category` | State institutions / political system | `target_state_institutions_political_system` |
| `data_theft` | Not available | `dtheft_not_available` |
| `disruption` | Long-term disruption (> 24h; incident scores 2 points in intensity) | `disrupt_long_term_disruption` |
| `hijacking` | Hijacking, system misuse… | `hijack_hijacking_system_misuse_e_g_through_data` |

17 of its 123 indicators are 1 and the other 106 are 0. Its numeric attributes are
`weighted_intensity` 4, `impact_indicator_score` 8, `affected_entities_value` 0 and
`affected_third_countries_value` 1.

### Check

`scripts/12_export_tables.py` recomputes the 123 indicators from the initial table and
stops if a single cell differs from `data/processed/features_matrix.csv.gz`.
